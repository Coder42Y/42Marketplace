# design-html

产出一个独立的 `.html` 文件,讲清楚思路、取舍和理由,不是技术文档。内容怎么组织、分几节、画哪些图,由你按内容判断。本文件只规定**交付物要达到的质量**。

## 1. 内容

- **大标题**(`<h1>` 和 `<title>`)是对文档主题的简洁陈述,用名词短语,不带口语、结论、情绪或设问。参考格式 `项目-主题-文档类型`。
  - ✅ `adrecta-eval-首跑结论`、`boban-审批流-重构方案`
  - ❌ `GLM 5.2 过了第一关,但这张卷子太简单`
  - 结论写在正文开头和每张数据图的标题里,不写进大标题。
- **多画图**。描述结构、流向、先后顺序、状态变化、前后对比时都用图,不写成大段文字。整体架构图是底线。每张图配一两句话说明看图重点:示意图写在图下方,数据图写成图上方的结论标题(第 3 节)。
- **有数字就用数据图或对比表**。方案之间比大小、随时间或规模变化、多方案多指标,都画出来(第 3 节),不写成段落里的一串数字。
- 不放代码片段(SQL/正则/schema/JSON)和过细的字段表,除非用户要。

## 2. 示意图(架构、流程、时序)

默认用内联 SVG 手绘,坐标和动画都可控。图复杂到手绘保证不了下面的标准时,可以改用 drawio 导出 SVG 嵌入。最终稿不用 Mermaid。

- **画机制,不画名字**。画出请求和数据真正走过的路径、跨过的边界。方案对比画同一张底图,高亮两个方案不同的那几条边,不要画成两排互不相连的方框。
- 每张图用 `<figure>` 包裹,`<figcaption>` 写看图重点;`<svg>` 加 `role="img"` 和概括同一重点的 `aria-label`。节点按 8px 网格对齐。

**走线**
- 线不穿过任何节点卡片,也不压文字(文字周围 4px 内没有线)
- 跨区域连线用正交折线。不同路径的两条线,水平段 y 不重合、垂直段 x 不重合,不能只差几像素。同一条主链上首尾相接的几段线可以在一条直线上
- 多个同等地位的来源进同一个目标:先汇成一根干线,只留一个箭头头
- 线上不写文字标签,用编号圆圈

**颜色语义**
- 一种颜色只表示一种含义。去程和回程语义不同时,颜色或线型也要不同
- 示意图里表达含义的每种颜色/线型,图例里都有;图例里没有的,图里不出现。泳道底色、节点白底这类中性色不算,不进图例。数据图不用这条,改用直接标注(第 3 节)
- 数据流箭头用下面三色。三色两两之间在色弱模拟和灰度下都能区分,不要换成别的颜色:

| 数据流 | 色值 |
|---|---|
| 主交互 / 发起动作 | `#142f4b` 深蓝黑 |
| 输出 / 结论 | `#cc3143` 正红 |
| 输入 / 素材流入 | `#6f35a2` 深紫 |

**动画**(可选):箭头用 `stroke-dasharray` 做流动,节点错开淡入。`prefers-reduced-motion` 时关掉。

## 3. 数据图与对比表

参考实现:`references/chart-sample.html`,包含数字卡、柱状图、折线图、对比表,双击可以直接看效果。画数据图或对比表前先打开它,复制对应区块的 HTML 和 CSS,再换成自己的数据。

**先选形式**

| 要说的是 | 用 |
|---|---|
| 一两个关键数 | 数字卡 |
| 几个方案或版本比大小 | 柱状图,可分组 |
| 随时间或规模的变化 | 折线图 |
| 多方案 × 多指标 | 对比表 |
| 程度递进的类别(弱 → 强) | 柱状图 + 红色阶 |

不用饼图、环形图、双 y 轴、雷达图、3D 图。

**每张图的结构**(对比表也一样)
- `<figure>` 包裹,`<figcaption>` 放在图的上方,分两行:
  1. **结论标题**:一句话说出这张图的看点。✅ `混合检索 v2 把召回率从 41% 提到 79%` ❌ `召回率对比`
  2. **灰色口径**:测的是什么、样本量、误差线的含义、是否对数刻度、测试条件。
- 图直接放在页面上,不套卡片,不加边框和阴影。

**颜色按实体分配**
- 同一个实体全文同一个颜色:它在柱状图里是蓝,在折线图和对比表的标注里也是蓝。
- 同一家族用同一色相:推荐方案或最新版用主色,同家族的旧版用浅色版(`-lt`);线上现状、对照组用灰。
- 家族按 蓝 → 绿 → 橙 → 紫 的顺序分配,推荐方案拿蓝。最多 4 个家族,再多就把次要的合并成「其他」,或者拆成两张图。
- 程度递进的类别(攻击强度、档位)用红色阶 `--red-1` → `--red-4`,由浅到深。
- 只用第 4 节 tokens 里的色值。它们已经过色弱和对比度校验,自己调色会破坏这一点。

**标注代替图例**
- 不画图例。柱子顶上标数值;折线在右侧列出「终值 + 名字」,按终值从高到低排。
- 数值和名字写成彩色字时用对应的 `-ink` 色,不用浅色版。对照组的字用 `--text-2`。
- 类目标签分两层:名称用黑字,日期或备注用灰字换行。
- 分组时写组名(名称 + 灰色限定语两行),组名下面画一条横跨整组的细线。
- 区分 0 和无数据:值为 0 时画一条贴底短线并标 `0%`;没法测的不画柱,画锁图标,下面用灰字写原因。
- 有置信区间就画误差线,口径里写明区间含义。

**线和轴**
- 网格线 1px 实线,只画 2–3 条;y 刻度只在最左边出现一次。基线比网格线深一档。
- 预算、上限这类阈值画成 1px 虚线,线端用灰字写明(如「产品上限 300ms」)。这是图里唯一允许的虚线,系列之间不靠线型区分。
- 柱子直角,不做圆角,宽度不超过 56px;折线 2.5px,线尾一个实心圆点。
- 多张图共用 x 轴时,轴标题只在最下面那张写。

**对比表**
- 推荐方案放在第一个数据列,整列加 3px 蓝框(`--focus`)。
- 每行最优值加粗并铺 `--hl` 底色;推荐列里的最优值用 `--hl-strong`。最优按指标方向判断:延迟、成本越低越好。
- 表头写方案名,下面灰字写身份(推荐、线上);行头写指标,下面灰字写口径。
- 格内数值靠左上对齐,条件或备注写在数值下一行的灰字里;缺数据写「—」。
- 全部单元格用 1px 深色网格线。

## 4. 视觉:暖白底,克制

全页暖白底,颜色只用来表达语义,不用来装饰。**全文不出现任何渐变**:背景、标题、按钮、SVG 填充都不行。

```css
:root {
  --bg: #fbf9f5;          /* 暖白底,全页统一 */
  --panel: #ffffff;       /* 示意图节点、正文里的卡片 */
  --panel-2: #f3f1ec;     /* 引用块、泳道 */
  --border: #dcd9d0;      /* 1px 细线,替代阴影 */
  --text: #1b1b1b;
  --text-2: #6b6964;      /* 次要文字、口径、图注 */
  --text-3: #73706a;      /* 坐标刻度 */
  --accent: #184ea4;      /* 唯一强调色,和图表的主色蓝相同 */
  --accent-soft: #dfe6e8;
  --ok: #2f7a4a;  --warn: #9a6212;  --bad: #b3362e;

  /* 数据图与对比表 */
  --grid: #e8e6e0;  --axis: #9c9990;  --rule: #1b1b1b;
  --hl: #dfe6e8;  --hl-strong: #c4d2df;  --focus: #6a9bcc;
  --blue: #184ea4;    --blue-lt: #89a9dc;    --blue-ink: #184ea4;
  --green: #109d7b;   --green-lt: #7db6a1;   --green-ink: #0c7b60;
  --orange: #c67625;  --orange-lt: #cb9d78;  --orange-ink: #a55f16;
  --violet: #a378c5;  --violet-lt: #b49dc8;  --violet-ink: #895faa;
  --gray: #9c9990;    /* 对照组、线上现状 */
  --red-1: #c66f73;  --red-2: #b84c55;  --red-3: #a12e3c;  --red-4: #821829;
}
```

- 字体全文只用一种无衬线:`-apple-system, "PingFang SC", "Noto Sans SC", "Microsoft YaHei", system-ui, sans-serif`。数字卡的大数字也不换字体
- 层次靠 1px 细线和留白来分,不用阴影
- 标题用纯色 `--text`。强调色一屏内只出现在少数地方
- 只做浅色主题。不用脉冲、hover 上浮这类装饰动效,表格行 hover 变底色就够

## 5. 移动端

文档常被转发到飞书/微信,用手机打开。375px 宽度下必须可读,且页面整体不横向滚动。

- 有 `<meta name="viewport" content="width=device-width, initial-scale=1">`;正文 `max-width: 880px`,两侧 16px 留白
- 卡片网格窄屏自动变单列;两栏对照窄屏改成上下堆叠
- 表格外包 `overflow-x: auto` 的容器,只让表格自己滚动;对比表的行头 `position: sticky` 固定在左侧
- 示意图 SVG 设 `width: 100%; height: auto`,viewBox 内字号 ≥ 13。宽图窄屏下改为容器内横滑(`min-width: 640px`),或者改成纵向布局
- 数据图的文字用 HTML 写,不用 SVG `<text>`,手机上字号才不会跟着缩小。做法照参考实现:柱状图整张用 HTML/CSS 画,折线图 SVG 只画线,刻度和线尾标签用 HTML

## 6. 交付标准

- 单个 `.html`,所有 CSS/JS/SVG 内联,双击即可打开。用了 drawio 的话,源文件留在同目录
- **交付前必须亲眼看过渲染结果**:截桌面(1440)和手机(375)两个宽度,对照第 1–5 节逐项检查,不过就改。改了三轮还有问题,就停下来告诉用户卡在哪里
  ```bash
  "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu \
    --hide-scrollbars --window-size=1440,2400 --screenshot=/tmp/d.png "file://$PWD/design.html"
  ```
  headless Chrome 有最小窗口宽度,`--window-size=375` 截出来会被裁切,浏览器 MCP 一般也打不开本地文件。手机宽度用 375px 的 iframe 嵌入 design.html 来检查:`grep` 那行应输出 `sw=375`,最后一行截图。检查完删掉临时页面
  ```bash
  echo '<iframe src="design.html" style="border:0;width:375px;height:9000px" onload="document.title=`sw=`+this.contentDocument.documentElement.scrollWidth"></iframe>' > _m375.html
  CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
  "$CHROME" --headless --allow-file-access-from-files --virtual-time-budget=3000 --dump-dom "file://$PWD/_m375.html" 2>/dev/null | grep -o 'sw=[0-9]\+'
  "$CHROME" --headless --disable-gpu --hide-scrollbars --allow-file-access-from-files --window-size=400,9000 --screenshot=/tmp/m.png "file://$PWD/_m375.html" 2>/dev/null
  ```
- 数据图逐张检查:有结论标题和灰色口径;没有图例、饼图、双 y 轴;0 和无数据画法不同;同一实体在各图同色;彩色文字用 `-ink` 色;对比表推荐列在第一个数据列,每行最优有高亮
- 全文搜 `gradient`,结果为 0
- 回复里用一两句话说明检查了什么、改了什么,不要只说"已生成"
