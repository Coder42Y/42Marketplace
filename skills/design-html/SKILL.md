# 把 idea 沉淀成设计说明 HTML

## 什么时候用

用户刚聊完一个想法、架构、方案,想要一份可分享、可打开的 HTML 说明文档。文档重点是讲清楚思路、方法、为什么这么选,而不是堆技术细节。

## 工作流

### 1. 先确认范围

不要急着写。先问清楚(或从上下文提取):

- 这份文档给谁看?同事?领导?自己备忘?(决定深度和语气)
- 要不要代码片段?多数情况下设计说明文档**不要代码**,讲思路就够。如果用户没说,默认不放代码,问一句确认。
- 有没有已经定下来的关键决策?如果有,整理成"决策记录"。
- 要不要架构图?默认要(这是 HTML 相比纯文本的最大价值)。

### 2. 架构图怎么画(让用户选)

**不要替用户决定画法。** 画架构图有三种方式,各有取舍。先跟用户说清楚,让他选:

| 方式 | 优点 | 缺点 | 适合 |
|---|---|---|---|
| **纯 SVG 手绘** | 完全控制坐标和动画,箭头流动效果最好,色弱友好 | 坐标要手算,线多时容易重叠,改起来累 | 图不太复杂(≤10 节点),要动画效果 |
| **codex + drawio skill** | 自动布局,可导出 .drawio/.png/.svg 多格式,可二次编辑 | 需要装 drawio CLI,动画要另加,配色要单独调 | 图复杂(>10 节点),需要可编辑的源文件 |
| **Mermaid** | 最快,代码即图,改方便 | 没法控制坐标,没动画,GitHub 原生渲染 | 草稿快速预览,不需要精致排版 |

**给用户的建议话术:**
> 架构图有三种画法:纯 SVG 手绘(动画好但坐标要手调)、codex 调 drawio skill(自动布局但要装 CLI)、Mermaid(最快但没动画)。你这个图节点不多又要动画,我建议纯 SVG。你想用哪种?

如果用户选 codex+drawio,调 `codex exec --skip-git-repo-check --sandbox danger-full-access` 跑 drawio skill,生成 .drawio/.png/.svg,然后把 SVG 嵌进 HTML。注意 drawio 的配色默认是冷色,要手动指定暖色色值。

如果用户没明确选,默认用**纯 SVG 手绘**(因为这是设计说明文档,动画和配色控制比自动化更重要)。

### 3. 文档结构(8 节)

按这个骨架组织,可根据内容增减:

1. **这个想法是什么** - 一两段话说清楚痛点和解决思路。结尾用一句引言点睛。
2. **整体长什么样** - 架构图。图下面一段话解释看图重点。
3. **几个关键选择** - 卡片式,每张卡写:选了什么 + 为什么。不写没选的选项细节。
4. **设计上的坚持** - 2-3 条贯穿始终的原则,每条配一句解释。
5. **流程怎么跑起来** - 编号步骤,纯文字叙述。点出人介入的环节。
6. **第一版做什么** - 做/不做两栏对照,讲清"先有骨架再长肉"。
7. **哪些地方会翻车** - 风险 + 对策表格。
8. **接下来怎么走** - 执行顺序,讲为什么这么排。

### 4. 画 SVG 架构图的规则(选了纯 SVG 时适用)

#### 布局

- 横向泳道布局:从左到右分区域,每个区域一个颜色容器框
- 泳道之间留垂直走廊(40-60px),数据流箭头走走廊,不穿过节点
- 节点用圆角矩形,高亮节点用更深的底色 + 粗边框
- 编号用彩色小圆圈 + 白字

#### 画箭头的核心约束(重要)

**每条线的水平段 y 坐标必须唯一,垂直段 x 坐标必须唯一。** 这是避免线重叠的根本规则。

具体做法:
1. 先列出所有节点边缘坐标
2. 给每条数据流分配独立的走廊 x 和水平 y
3. 逐对验证:任意两条线的水平段 y 不同,垂直段 x 不同
4. 跨泳道箭头用正交折线(水平-垂直-水平),不用斜线曲线

如果发现两条线必须交叉,说明布局需要调整--要么挪节点,要么给某条线换一条走廊。**不要靠"差几像素"来勉强避开**,差 5px 视觉上还是糊在一起。

#### 动画

- 数据流箭头用 `stroke-dasharray` + `stroke-dashoffset` 动画,持续流动
- 节点用 `nodeIn` 动画逐个淡入(按 delay 错开)
- 泳道用 `laneIn` 淡入
- 配 `prefers-reduced-motion` 时关掉动画(可选)

### 5. 配色(Anthropic 文档风格)

**不要白蓝冷色调。** 用 Anthropic 暖色系:

```css
--bg: #f5f4ee;          /* 暖米底 */
--panel: #faf9f5;       /* 米白卡片 */
--text: #1a1816;        /* 暖黑文字 */
--accent: #cc785c;      /* 棕橙强调(标题渐变、主色) */
--accent-2: #5c4a3a;    /* 深棕次要 */
--green: #5c7a4a;       /* 橄榄绿(用于"飞书""成功"类元素) */
--orange: #b86a3c;      /* 暖橙(用于"代码""Git"类元素) */
```

架构图箭头用**色弱安全高对比度三色**(明度差异大):

| 数据流类型 | 颜色 | 色值 |
|---|---|---|
| 主交互流(如 leader↔服务器) | 深蓝黑 | `#1a3a5c` |
| 输出流(如 服务器->飞书) | 正红 | `#c41e3a` |
| 输入流(如 代码提交->服务器) | 深紫 | `#5b2c8a` |

泳道颜色可以保留各自语义色(暖绿/暖橙/暖棕),但**数据流箭头必须用上面三色**,因为泳道靠位置就能区分,箭头必须靠颜色区分。

如果用 codex+drawio 画图,在 prompt 里明确指定这些色值,drawio 默认配色是冷色的。

### 6. SVG 响应式(选了纯 SVG 时适用)

架构图要**完整撑开在页面里**,不要横向滚动:

```css
.arch-svg { width: 100%; height: auto; }
```

去掉容器的 `overflow-x: auto`。viewBox 保持固定比例,让 SVG 按容器宽度等比缩放。

### 7. 不要放的东西

- 代码片段(SQL/正则/schema/JSON 示例)--设计说明文档讲思路,不堆代码
- 过细的字段表(类型、写入方这种)--除非用户明确要
- 在线上加文字标签--太挤,用编号圆圈就够
- 深色主题--用 Anthropic 暖色浅色主题

### 8. 交互细节

- 顶部 badge 放版本号(如 `ver 1.0`),带脉冲点动画
- 决策卡片 hover 上浮
- 步骤列表 hover 右移
- 表格行 hover 高亮
- 标题用渐变色(棕橙 -> 深棕)
- 章节进入视口时淡入上滑

## 输出

一个独立的 `.html` 文件,双击可打开,不依赖任何外部资源(所有 CSS/JS 内联,SVG 内嵌)。如果用 codex+drawio,生成的 .drawio/.png/.svg 作为附带文件留在同目录,HTML 里嵌入 SVG。

## 反例(避免这些坑)

- ❌ 不问用户就用某一种画法 -- 要先给建议让用户选
- ❌ 用 Mermaid 画架构图想加动画 -- Mermaid 生成的 SVG 没法精确控制坐标和动画,要动画就用纯 SVG
- ❌ 纯 SVG 箭头用斜线/曲线跨泳道 -- 必然穿过节点,造成重叠
- ❌ 多条线共用同一个 x 或 y 坐标段 -- 必然重叠
- ❌ 用白蓝冷色 -- 不是 Anthropic 风格
- ❌ 放代码片段 -- 设计说明不是技术文档
- ❌ 图被框在横向滚动容器里 -- 应该完整撑开
- ❌ 线上堆文字标签 -- 太挤,编号圆圈就够
- ❌ 箭头颜色明度接近 -- 色弱看不清,用高对比度三色
