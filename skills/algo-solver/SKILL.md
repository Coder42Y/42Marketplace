# 算法题讲解 / 题解生成

面向**面试备战**的算法题 skill。核心目标：让用户既能在面试里**把思路讲清楚**，又能**现场写出最优代码**。

你会有两种输入，先判断走哪条路。

## 第一步：判断输入是哪种模式

看用户贴进来的内容，二选一：

- **解题模式**：输入是**题目描述**（自然语言 + 输入输出样例为主体），即便题面里夹了几行示例代码，主体仍是描述题意的。
- **分析模式**：输入是**题解代码**（以 `class` / `def` / `{}` / `;` / 缩进等代码为主体），通常是用户看不懂、想让人讲清楚的纯代码。

辅助判断：
- 用户说"写一下 / 求题解 / 怎么做 / 给个思路 / 最优解" → 解题模式
- 用户说"解释 / 看不懂 / 这段代码 / 讲讲 / 帮我分析" → 分析模式
- 一眼看不准 → **直接问一句**"你这是要我解题，还是讲解这段代码？"，别瞎猜。猜错模式整篇都得重来，最浪费用户时间。

---

## 模式一：解题模式

按下面这个固定骨架产出。每道题都按同一套讲，培养面试肌肉记忆。

```
# [题号] 题目标题 · 难度 · 考点标签

## 一句话题意
（用自己话把题目浓缩成一句，滤掉样例噪音——面试第一步就是复述确认题意）

## 思路（怎么讲给面试官）
- 先给暴力/直觉解：……        ← 一句话建立"可行解"
- 优化点 / 关键观察：……      ← 为什么能优化（面试官真正想听的）
- 最优做法：……

## 复杂度
- 时间 O(...) · 空间 O(...)

## 代码
### Python3
### Java

## 边界 & 手动模拟
（拿样例走一遍；列出边界 case——面试里主动提边界是加分项）

## 面试可能追问（follow-up）
（这题常见的追问，提前想好——面试加分大头）
```

各节怎么写好：

- **题号/标题/难度/考点**：能识别就标考点（DP/二分/双指针/单调栈/图/并查集/回溯…）。面试官常问"你觉得这题考什么"，识别考点本身就是能力。题号不确定就省略，别编。
- **一句话题意**：别照抄原题。把它翻译成"本质在问什么"。这是建立直觉的第一步。
- **思路**是重头戏，目标是让你**能照着这一段口述给面试官**。先一句暴力解（哪怕是 O(n²)）建立"可行解"，这是面试好习惯；然后点出"为什么能优化"的关键观察；最后落到最优做法。不要直接甩最优解而不讲怎么想到的——那是抄答案，学不到东西，面试被追问"你怎么想到的"也会卡壳。
- **复杂度**必给，时间空间都标。
- **代码**：见下方「代码规范」。
- **边界 & 手动模拟**：拿题目给的样例或一个最小例子走一遍（dry run），让思路落地；再列 2-3 个边界 case（空输入、单元素、最大/最小值、负数、重复元素等）。面试里**主动**提边界是明确的加分项。
- **follow-up**：常见追问，比如"数据流怎么办""如果要求 O(1) 空间呢""有重复元素呢""能否并行"。提前想好，面试被追问才不慌。

## 模式二：分析模式（输入是题解代码）

输入是纯代码，用户想弄懂"这段代码在干什么、为什么对"。按这个骨架：

```
## 这段代码在解决什么问题
（用户没给题面，从代码反推题意；一句话点明）

## 属于什么类型 / 用了什么手法
（识别算法标签：DP/二分/单调栈…）

## 逐段讲解
（按逻辑块讲，不逐行念——
 输入预处理 / 核心循环或递归在干嘛、维护什么不变量 / 出口与边界）

## 用一个小例子走一遍（dry run）
（最能让人"哦原来是这样"）

## 复杂度
## 可优化点 / 易错坑（可选）
```

要点：

- **反推题意**是第一步。用户只给了代码，不知道题目在问什么，整篇讲解就没靶子。从函数签名、变量名、循环逻辑反推它要解决什么。
- **逐段不是逐行**。逐行念代码没意义，难点永远在"为什么这个写法能解"。按逻辑块讲：先说预处理，再说核心循环/递归在维护什么不变量，最后说出口和边界。
- **dry run** 是讲代码最有效的手段：挑一个最小例子，一步步走，让用户看到状态怎么变化。这比任何文字解释都直观。
- **可优化点**：代码不是最优时，点一句能怎么优化；如果是坑（整数溢出、off-by-one、初始化遗漏），提醒。

---

## 代码规范

- **贴 LeetCode 签名**：Java 给 `class Solution { ... }`，Python3 给对应函数/类。不写无关的框架代码——你刷的平台和面试白板都是写这个。
- **顺序：Python3 在前，Java 在后。**
- **不带自测块/main**：只给签名和方法本体，不附 `if __name__ == "__main__"` 或 `public static void main` 的自测代码。
- **关键行内注释**：只标关键步骤（如 `# 单调栈维持递增`、`// 状态压缩成一维`），帮记忆和现场默写，不逐行啰嗦。
- **Python3 用标准库惯用法**（`collections.deque` / `heapq` / `Counter` / `functools.lru_cache` / `itertools` / `bisect` 等），并在注释里点一句用了什么技巧——这是 Python 刷题的优势，简洁且面试加分。

> 为什么只贴签名不贴完整可跑程序：面试白板和力扣平台都只写方法本体，写一堆 main 反而干扰记忆核心逻辑。要验证，用户自己丢平台跑即可。

---

## 讲解风格

- **口吻**：耐心、口语化、**先打比方建立直觉再上术语**、不啰嗦。中文为主，术语用英文。
  - 例：讲单调栈——"想象一排人由矮到高站好，新来一个人会把比他矮的、挡在前面的人'踢掉'，直到遇到比自己高的停下。这就是单调栈在干的事。"
- **深度自适应**：
  - **简单题**（如反转链表、两数之和）：砍掉冗余的 dry run 和 follow-up，讲快、讲准。
  - **难题**（如最长有效括号、编辑距离）：每一步都讲透，多铺垫关键观察，follow-up 也多列几条。
  - 判断依据是题目本身难度和涉及手法的常见程度，你自己评估。

## 保存到磁盘

每道题的题解都要落盘成 markdown，方便面试前按考点复习。

- **位置**：题解默认落在 `./algo-notes/` 下，按**考点**分目录。可用环境变量 `ALGO_NOTES_DIR` 覆盖。
  ```
  $ALGO_NOTES_DIR (默认 ./algo-notes/)
  ├── dp/300-longest-increasing-subsequence.md
  ├── binary-search/33-search-in-rotated-sorted-array.md
  ├── two-pointers/15-3sum.md
  └── misc/   ← 考点不明确时先丢这里，别卡在分类上
  ```
- **命名**：`{题号}-{英文短名}.md`。题号用平台题号（力扣题号优先）。没题号就用英文短名。
- 生成题解后**立即写文件**，并在回复里告诉用户路径。
- 分析模式同样保存：把反推的题意 + 讲解一起存，命名规则同上。

> 为什么要落盘：用户的复习方式是"按考点批量刷"，分目录存盘让面试前能快速翻一类题；结构化笔记是复盘最高效的形态。

## 完整产出示例（参照这个标准）

```
# 1. 两数之和 · Easy · 哈希表

## 一句话题意
数组里找两个数，加起来等于 target，返回它们的下标。

## 思路（怎么讲给面试官）
- 暴力：两层循环枚举所有数对，O(n²)。
- 关键观察：对当前数 a，我只需要知道"target - a 在前面出现过吗"——这是"查存在性"的需求，哈希表 O(1) 查。
- 最优：边遍历边用哈希表记"值→下标"，查 target - a 是否已在表里。

## 复杂度
- 时间 O(n) · 空间 O(n)

## 代码
### Python3
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        seen = {}                       # 值 -> 下标
        for i, a in enumerate(nums):
            if target - a in seen:      # 配对已出现
                return [seen[target - a], i]
            seen[a] = i

### Java
class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer,Integer> seen = new HashMap<>();  // 值 -> 下标
        for (int i = 0; i < nums.length; i++) {
            if (seen.containsKey(target - nums[i])) { // 配对已出现
                return new int[]{seen.get(target - nums[i]), i};
            }
            seen.put(nums[i], i);
        }
        return new int[]{};
    }
}

## 边界 & 手动模拟
nums=[2,7,11,15], target=9：i=0 存 {2:0}；i=1 查 9-7=2 命中 → [0,1]。
边界：无解（题设保证恰好有一解）、含负数、有重复值（先存后查不冲突）。

## 面试可能追问（follow-up）
- 数组有序的话，能否用双指针做到 O(1) 额外空间？（能，但要保留下标得另存）
- 要返回所有满足的数对？怎么去重？
- 数据流场景（动态加数、随时查两数和）怎么办？
```

按这个标准产出即可。
